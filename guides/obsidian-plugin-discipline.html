不要掉进“插件越多，系统越强”的陷阱

Obsidian 的可扩展性很强，但知识系统应该先在没有 Community Plugins 的情况下成立。

Obsidian 官方确实提供 Core Plugins、Community Plugins、Themes、CSS Snippets、Web Clipper、CLI 等大量扩展能力。问题不是插件不好，而是插件很容易把“知识管理”变成“配置管理”。

1先理解

先抓住这篇教程要解决的核心问题。

2再动手

按顺序完成设置，把步骤放进真实工作流。

3最后验证

用一个小场景确认它真的节省了时间。

典型的插件陷阱

看到 Dataview、Tasks、Calendar、Templater、Kanban、Excalidraw……每一个都很有吸引力。于是你开始安装、调参数、改主题、解决冲突，最后一天过去了，真正的笔记并没有增加。

先问一个问题：如果今天把所有 Community Plugins 都关掉，我的知识库还能不能继续工作？如果答案是否定的，说明系统过度依赖插件。

先建立无插件底座

底座只依赖 Markdown、文件夹和链接：

Inbox → 捕捉
Projects → 当前上下文
Knowledge → 长期知识
MOC → 主题导航
Archive → 已结束内容

只要这五层能够工作，你以后换主题、换插件，甚至换软件，知识结构都不会崩。

插件什么时候值得装

当你能非常具体地描述问题时再装。例如：“我每天都要手工把同类笔记做汇总，重复操作十分钟”，这时 Dataview 类插件可能有价值。

如果理由只是“别人都装”“看起来很酷”“可能以后会用”，先不要装。

MOC 比很多自动化更值得先学

自动生成的知识图谱很漂亮，但它很难替代你主动建立的主题结构。一张简单的 MOC，可以明确表达“这些概念为什么属于同一个主题”，而不是只显示它们碰巧有链接。

我建议的插件纪律

  1. 每装一个插件，写清它解决什么问题。
  2. 优先使用 Core Plugins 能解决的能力。
  3. 每个月检查一次长期不用的 Community Plugins。
  4. 不要让关键数据只存在某个插件私有格式里。

判断系统有没有变强

不是看插件数量，而是看三个指标：记录更快、找回更快、旧知识更容易被重新使用。
