不要一开始做复杂 Dashboard

Notion 真正重要的不是封面、Emoji 和首页，而是 Page 与 Database 这两个基础对象。

很多人第一次用 Notion，会先复制一个看起来很厉害的 Dashboard。两周以后，真正的问题不是页面不够漂亮，而是自己根本不知道哪些信息应该放进去、哪些状态需要维护。

先理解 Page

Page 就是一张可以承载内容的页面。项目说明、会议记录、方案、笔记、任务详情都可以是 Page。Notion 的 Database 里，每一条记录本身也可以打开成独立 Page。

再理解 Database

Database 用来管理“很多个相似对象”。例如任务很多以后，你需要 Status、Due Date、Priority；项目很多以后，你需要 Stage、Owner、Next Step。这时数据库才开始有价值。

Notion 官方当前支持同一数据库使用 Table、List、Board、Gallery、Calendar、Timeline，以及 Chart、Form、Map 等多种视图。新手完全不需要一次学完。

判断要不要建数据库：只有一条信息，先写 Page；当同类信息不断重复，而且你开始需要筛选、排序、状态管理时，再 Database 化。

最小结构只做三个入口

Home

只当导航，不要把所有信息都塞进首页。

Inbox

暂时不知道放哪里的东西先进来。Inbox 的价值是让“记录”不需要先做分类决策。

Projects

把真正正在做的项目放进一个 Database。第一版属性甚至只需要：Name、Status、Category、Next Step。

Home
├── Inbox
└── Projects
    ├── Name
    ├── Status
    ├── Category
    └── Next Step

先不要做的事

不要第一天就建立十个数据库、几十个 Relation、复杂 Formula、自动化和模板库。一个系统的维护成本如果高于它帮你节省的时间，它就已经失败了。

Notion 的真正目标

不是“我的主页够不够酷”，而是：明天打开以后，我能不能马上知道现在有什么项目，以及下一步该做什么。
