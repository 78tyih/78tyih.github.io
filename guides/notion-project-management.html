一个数据库，做出四种工作视图

不要为了“不同场景”复制四套任务。数据只有一份，View 才是观察它的不同角度。

Notion 最容易用复杂的地方，是你开始为“今天要做什么”“全部任务”“本周任务”“高优先级任务”分别建不同表。其实这些通常不是四类数据，而是同一批任务的四种观察方式。

先把 Tasks 数据库压到最小

第一版只需要：Task、Project、Status、Priority、Due Date。不要为了“以后可能会用”先加十几个属性。

Task
Project
Status
Priority
Due Date

View 1：All Tasks

用 Table 作为完整管理视图。这里负责查看全部属性、批量修改、整理数据。它不是日常最常看的页面，而是后台总表。

View 2：Doing

用 Board 或 List，只显示 Status = Doing。这个 View 的作用不是展示完整信息，而是降低注意力成本：今天工作时，只看正在推进的东西。

View 3：Calendar

按 Due Date 展示。Calendar 的价值不是让页面更漂亮，而是帮助你发现时间冲突——比如同一天是不是塞了五件实际上不可能完成的事。

View 4：Priority

过滤 Priority = High，再按 Due Date 排序。它是“当所有事情都很吵时，我到底应该先看什么”的视图。

Notion 官方的核心逻辑也是一样：同一数据库可以创建多个 View，并分别设置过滤、排序、分组和布局，而不需要复制底层数据。

什么时候再加 Project ↔ Tasks

当你已经稳定使用 Tasks 和 Projects 一段时间，而且经常需要回答“这个项目还有哪些任务没做”，再建立 Relation。不要因为教程里能连，就第一天全部连起来。

最后看一个指标

一个项目管理系统真正应该优化的是：你从打开 Notion 到知道下一步做什么，需要多少秒。如果答案是五分钟，那它再漂亮也不够好。
